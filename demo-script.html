1 · 先背这三句（全部内容的骨架）

1. A harness has only two jobs: hand the task to the model, and get the answer back reliably.
2. We split it into a general layer that is identical for every task, and a solver layer that we replace per task.
3. Only one task got a full solver, so that one is stable; the rest run on the general agent — and that is exactly where our failures came from.
三句话的意思：① harness 只有两个职责；② 我们分成“通用层 + 专用求解层”；③ 只有一个任务有完整求解器，所以它稳，失败也都出在没有求解器的任务上。

2 · 8 分钟逐页口播

P1 · 架构：两层，各管一件事 1:00

A harness has only two jobs. First, hand the task to the model with the right context. Second, get a valid answer back to the grader. Those are different problems, so we separated them.

The general layer is identical for every task: it builds the prompt, launches the native CLI, enforces the time budget, and makes sure something valid is submitted before the clock runs out. The solver layer is task-specific physics — and we only wrote it for one task.

This split matters because it makes failure diagnosable. When a task fails, the question becomes: did the model not know the physics, or did the delivery layer lose the answer?
“One layer talks to the platform, the other does the physics.”

P2 · 成功案例：net-zero CZ（386 秒，得分）2:30

This task asks us to characterise a tunable coupler and program a net-zero CZ gate, on a device whose parameters we are not told.

We turned it into a fixed pipeline. First, a square-step cryoscope measures how the flux line settles, and we fit two poles to it. Second, a two-dimensional chevron locates the |11>-|02> crossing and gives us the coupling. Third, we design a mirrored trajectory that is net-zero by construction, and predistort it with the exact inverse of the settling we just measured. Finally, we close the conditional phase on shot data — we measure it, we do not predict it — and verify leakage and single-qubit phases before submitting.

Every number comes from measurements on that cooldown. Nothing is assumed from a notebook. It finishes in 386 seconds and it scores.
“We measure the device, we do not assume it — and the pulse is the inverse of what we measured.”

P3 · 失败案例：H₂O 复合测量为什么是 0 分 2:00

This task has an 1800 second budget, and it has a one-shot lock: you design a measurement scheme, lock it, and run production exactly once.

In our trace, the agent reached 97.6 percent of its budget before it decided to lock. Everything before that was comparing control-variate choices — one hundred and five Z-only terms against eighty-seven off-diagonal ones, whether to shrink or not. It was not that the model could not do the physics; it could not stop optimising. And because the lock is one-shot, locking at 97 percent means there is no time left to run production and submit.

That failure produced our first rule: for any one-shot task, lock by 60 percent of the budget. Not because the design is perfect, but because an unsubmitted design scores zero.
“It was not a physics failure, it was a decision-timing failure.”

P4 · 通用层：从失败里提炼的三条纪律 1:30

Three rules came directly out of the traces.

One: insurance submission. As soon as a complete answer exists, submit it, then keep improving. Most tasks score the latest submission, so an early answer costs nothing.

Two: never guess platform internals. In another task the agent spent eight hundred seconds trying to reverse-engineer a twelve-character identifier with hash functions. A required identifier is returned by a tool — you copy it, you do not search for it.

Three: batch only when the result mapping is guaranteed. Batching saves connection time, but a misassigned result corrupts an entire answer, so when the task does not document ordering, we call serially.
“Every rule we added came from a specific trace we could point at.”

P5 · 结果 0:30

Across the full evaluation we passed 26 of 39 tasks, at about 3356 seconds per task. On the five public tasks we passed three: the CNOT decoder, Hamiltonian learning, and the net-zero CZ. The two we missed are both 1800 second tasks that need heavy numerical modelling written from scratch inside the run.

P6 · 可复用性 0:30

To reuse this on a new task you add one solver file and one exact routing rule. The general layer does not change. The code is released under AGPL-3.0-only, with the upstream MIT notice retained, a build file and a change log — so another team can reproduce exactly what we ran.

3 · 7 分钟问答：五个必答题

评委可能问你这样答（英文口播）
Why did CZ succeed while H₂O failed? “The difference is whether a dedicated solver existed, not the model strength. CZ had a measured pipeline; H₂O had an agent writing numerical code from scratch under a 1800 second budget.”
What are the 13 failures? “On the public set the two failures are both 1800 second tasks that need heavy numerical modelling. Hidden-task details are not visible to us, so I can only describe them by budget and task shape, and I will not guess beyond the evidence.”
How do you guarantee reproducibility? “Scan resolution is a deterministic function of the budget, the fits are deterministic, and the submitted archive is frozen by SHA-256. Re-running the same frozen candidate reproduces the same behaviour.”
How much work to reuse it? “One solver file plus one exact routing rule. The general layer stays untouched, and the CZ path is byte-identical to what was evaluated.”
Is the licensing compliant? “Our additions are AGPL-3.0-only. The upstream starter files keep their MIT notice and are not relicensed. Dependencies are BSD and MIT, and nothing is vendored.”

4 · 不会答的时候怎么说（万能三句）

A. “I do not have that number in front of me — I can follow up with the exact figure after the session.”
B. “That is outside what we measured; I would rather say I do not know than guess.”
C. “What I can tell you from the trace is …” (then say the one thing you do know)
关键：永远不要编数字。评委给了 40% 权重给可靠性，编一个数被识破，比说“我不知道”损失大得多。

被质疑分数不高时

“26 of 39 is the honest result of this design. Most of the gap is tasks that need a per-task solver we did not have time to validate. We chose not to ship unvalidated solvers, because a wrong solver scores zero and also risks the tasks that already work.”
这句话同时回答了“为什么不再冲高”和“你的判断力在哪里”——这正是可靠性评分想看的东西。
